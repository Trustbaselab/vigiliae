# 决策闭环（Decision Loop）

## 何时使用

- 用户拿到了结论，但不知道下一步做什么
- 产品只交付「数据/报告」，客户看完就结束
- 要判断一个数据/AI 产品是「建议者」还是「参与者」
- 设计一个业务闭环，需要确认它真的闭合

**不适用**：

- 只是要一份数据汇总 → 直接用查询工具
- 只是要一份研究报告 → 用写作类 skill

---

## 核心判断：六段链路里，你卡在第几段

Palantir AIP 把企业 AI 拆成六段。**多数产品停在第三段之后。**

| 段 | 内容 | 常见状态 |
|:-:|---|:-:|
| ① | **读懂业务**：业务对象是什么、彼此怎么关联（语义层） | 很多公司缺 |
| ② | **数据接入 + 口径对齐**：把散在各处的数据接进来并统一口径 | 多数公司能做 |
| ③ | **模型 + 专用算法编排**：大模型负责理解推理，数值/优化交给专用算法 | 多数公司能做 |
| **④** | **把结论变成动作**：发策略、推执行、触发流程、**回收结果** | ⭐⭐ **分水岭** |
| ⑤ | **权限与合规**：能不能进强合规行业 | 看行业 |
| ⑥ | **复用**：第二个客户的建设成本比第一个降多少 | ⭐⭐ 产品化分水岭 |

> **第 ④ 段的分界线在于：结论交出去之后，系统负不负责？**
> 不负责 → 你只是「建议者」，结论变成动作由人或别的系统完成，反馈很少回流。
> 负责 → 你是「参与者」，回路闭合，系统能从结果里修正自己。

---

## 执行流程（五步）

### ① 找到「本来就有的执行方」

**这是整件事最关键的一步，也是多数人跳过的一步。**

一个动作能闭合，前提是**已经有人/系统在执行它**。你要找的不是「新建一个执行流程」，而是「接上一个已有的执行方」。

| 场景 | 天然的执行方 | 为什么容易闭合 |
|---|---|---|
| 广告投放建议 | 投放系统 / 优化师 | 本来每天就在调价调量 |
| 采购牌号判定 | 采购员 / 质检员 | 本来每批货都要判 |
| 合规义务判定 | 关务 / 法务 | 本来每次出口都要过 |
| 设备异常预警 | 运维 / 值班 | 本来就要处理告警 |

**❌ 找不到执行方 → 这个闭环做不成，别硬做。**

### ② 定义「动作的最小单位」

不要设计「生成一份报告」，要设计「触发一个可追踪的动作」。

```
❌ 弱动作：「这是一份牌号判定报告」
✅ 强动作：「这批货判定为 N660 而非标示的 N550，
           建议：① 拒收或要求供应商降级报价 ② 复测灰分
           动作方：质检员 → 一步可执行」
```

**判断标准**：动作方看完后，**不需要再做二次判断**就能执行。

### ③ 把「反馈」设计进流程

没有反馈的闭环等于没闭合。

```
最低要求：动作执行后，记录「采用 / 未采用 / 采用后结果如何」
进阶要求：结果回流成「判定是否准确」的训练信号
```

**⭐ 反馈回收的三个层次：**

| 层次 | 形式 | 价值 |
|:-:|---|---|
| L1 采用率 | 用户点「采纳」/「忽略」 | 知道结论有没有用 |
| L2 结果 | 用户回填「执行后结果」 | 知道结论对不对 |
| L3 归因 | 系统对比「预测 vs 实际」 | 能训练模型 |

**只做 L1 也比不做强 10 倍。**

### ④ 检查权限与合规

```
· 这个动作需要什么权限才能触发？
· 触发后谁负责？（不能是「系统自动」这种模糊说法）
· 出错了谁承担？
· 有没有强合规要求（审计留痕、双人复核、数据出境）？
```

**⭐ 强合规行业的动作必须有：可追溯的执行日志 + 明确的审批链。**

### ⑤ 验证复用成本是否下降

**这是「项目制」和「产品化」的唯一分界线。**

```
问三个问题：
① 第二个客户上线，需要多少人天？比第一个降了吗？
② 能力沉淀在平台上，还是沉淀在实施工程师脑子里？
③ 换个行业/场景，要重写多少？
```

**⭐ 如果第二个客户成本没降 → 你是项目公司，不是产品公司。**

## 输出模板

设计或评估一个决策闭环时，输出这五项：

```markdown
## 决策闭环设计

### ① 业务对象与关系（语义层）
| 对象 | 关键属性 | 与其他对象的关系 |

### ② 数据来源与口径
| 数据 | 来源 | 口径 | 可信等级 |

### ③ 结论生成方式
| 结论 | 用什么算 | 依据 |

### ④ 动作（关键）
| 结论 | 触发什么动作 | 执行方 | 执行后如何回收 |
⭐ 至少要有一行「执行方」是真实存在的角色

### ⑤ 反馈与复用
| 反馈层次 | 采集方式 | 用在哪 |
| 第 2 个客户成本 | 预估人天 | 比第 1 个降 % |
```

## 判据速查

**一个闭环成不成立，看这四条：**

| 检查 | 不通过的表现 |
|---|---|
| 有没有真实执行方接住动作 | 「建议甲方自行决定」 |
| 动作是否单步可执行 | 用户看完还要再问一轮 |
| 反馈是否回流 | 交完就结束，永不知道对错 |
| 第二客户成本是否下降 | 每次都要从零配 |

---

## 诚实边界

- 本 Skill 是流程与判据，不含任何行业数值或法规内容
- 「执行方」必须真实存在。找不到执行方时，**明确说「此场景闭环不成立」**，不要设计一个假想执行方
- 反馈层次能做到 L1 就算及格，**不要声称有 L3 能力而没有实际回流数据**
- 行业合规要求以实际法规为准，本 Skill 只提醒「要检查」，不代替法务判断
