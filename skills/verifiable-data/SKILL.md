# 可信数据生产法

## 何时使用

- 要建一个「别人可以质疑」的数据集
- 数据要用于对外披露、登记、申报、授权
- 有人问「你的数据凭什么可信」
- 要做数据质量审计

**不适用**：

- 只是自己用的草稿数据 → 不需要这么重
- 纯粹的分析报告 → 用写作类 skill

---

## 核心原则：三个「不可」

```
① 不可编造 source_url —— 没亲自取到就不写 URL
② 不可编造 quote —— 必须是页面逐字子串，不是概括
③ 不可编造 as_of —— 页面没写就用取回日期并注明
```

**违反任何一条，整条记录降为 E 级。**

---

## 五级置信度（A–E）

| 级别 | 含义 | 判定条件（必须全部满足） |
|:-:|---|---|
| **A** | 权威一手 | ① 来源是发布方自己的正式文件/数据表/官方页面 ② 实测 HTTP 200 ③ quote 是页面逐字子串 ④ as_of 来自页面 |
| **B** | 权威二手 | 数字被归因于某个一手源，但你没能亲自取到那个一手源 |
| **C** | 一般二手 | 二手转述，无明确一手源指向 |
| **D** | 存疑 | 来源存在但内容有内部矛盾，或口径不明 |
| **E** | 不可核验 | 取不到（403/付费墙/robots 禁止）、或无法确认 quote、或来源已消失 |

**⭐ E 级不是「坏数据」，是「线索」。诚实标 E 比伪装成 A 有价值 100 倍。**

---

## A 级双轨分层（关键）

**同样是 A 级，「行业相关」和「宏观统计」的价值完全不同，必须分开披露。**

| 档 | 定义 | 例子 |
|:-:|---|---|
| **A1** | 行业相关：政府机关 / 标准组织 / 厂商官网技术数据表 | 某部委文件、ASTM 标准原文、厂商产品 datasheet |
| **A2** | 宏观统计：国际统计库，公开发布，任何人免费可得 | World Bank / UN Comtrade / EIA |

**为什么必须分：**

```
如果只报「A 级 87%」→ 看起来很好
但其中 86% 是 World Bank/UN 宏观数据（客户自己就能免费拿）
→ 一旦客户发现，信任崩塌

分轨披露「A1 13% / A2 86%」→ 难看但真实
→ 客户知道你的核心资产在哪
```

## 执行流程（六步）

### ① 先定 schema，再采数据

**不要先采再想字段。** 每条记录必须固定的字段：

```
id              稳定唯一标识（前缀 + 日期 + 序号）
type            领域/类型
public.*        公开可展示字段（名称/地区/发布方/状态）
sourced.source_url     来源页 URL
sourced.quote          页面逐字子串（≥20 字符）
sourced.confidence     A | B | C | D | E
sourced.verification   核验方式说明（怎么验的）
as_of           数据时点（YYYY-MM 或 YYYY-MM-DD）
evidence.*      指纹/取回时间/来源快照
```

### ② 采一条，验一条

```
每采一条立即做三件事：
① curl 一遍 source_url，记 HTTP 状态码
② 在页面里搜 quote，确认是逐字子串
③ 记录取回时间
```

**批量采完再统一验 = 必然有一批过不了，且不知道哪条错。**

### ③ 采不到就标 E，写明原因

```
E 级的 verification 必须写清：
· 403 → 「官网返回 403，无法读取」
· robots → 「robots.txt 禁止抓取」
· 付费墙 → 「标准全文需购买」
· quote 找不到 → 「页面内未找到该数值」
```

**⭐ 写清原因的 E 级 = 有价值的情报（告诉人这条路走不通）。**
**⭐ 不写原因的 E 级 = 垃圾。**

### ④ 分轨统计，不要混报

```
输出统计时给两套数：
· 全局 A 级占比（含 A2 宏观）
· A1 行业相关 A 级占比（这才是核心资产）
```

### ⑤ 锁定标的指纹（防篡改）

```
对外承诺一个固定数据集（如「登记标的」）时：
① 算 SHA-256 并对外公布
② 每次写库前自动校验该 hash
③ hash 变了就 abort，不允许继续
```

**⭐ 这是「你的数据没被偷偷改过」的唯一技术证明。**

### ⑥ 唯一性与完整性三查

```
① ID 重复？
② 主键（key）重复？
③ 名称重复？（允许，但必须标 duplicate_of）
④ 必填字段缺失？
⑤ A 级是否都有 source_url？
⑥ E 级是否都写了「未核验」原因？
```

## 数据质量自评模板（对齐 T/CIIA 060-2025）

国标《数据质量鉴证评价方法》七个维度，可自查：

| 维度 | 标准问什么 | 怎么自证 |
|:-:|---|---|
| ① 规范性 | 命名/定义/结构/取值规范 | 有 schema 版本号 |
| ② 完整性 | 必填字段齐全度 | 跑一遍缺字段统计 |
| ③ 准确性 | 数据正确性 | 分层抽样验 source_url + quote |
| ④ 一致性 | 跨表/跨源一致 | hash 校验 + 同名对照 |
| ⑤ 时效性 | as_of 时效 | 统计 as_of 分布 |
| ⑥ 安全性 | 访问控制 | 分层授权 + 敏感字段剥离 |
| ⑦ 权属性 | 来源可追溯 | source_url + quote 覆盖率 |

**⭐ 五项以上能满足即可对外称「按国标七维度自评 X/7」。**

## 常见陷阱（血的教训）

| 陷阱 | 后果 | 正确做法 |
|---|---|---|
| 用「顶层 name」判空，没看 `public.name` | 误判数据脏 | **判断字段缺失前先 dump 一条完整记录** |
| 修复范围凭增量猜测 | 修了 8,790 条而不是 118 条 | **先统计受影响总数，区分「历史遗留」vs「新引入」** |
| 只查 subdomain/domain，漏看一直存在的 type | 7,079 条被错标 unknown | **枚举全部字段再判断缺什么** |
| API 端点返回 401 仍标 A 级 | 客户点进去看到 401 | **需 subscription key 的降为 B** |
| 采完不验就当 A | 一批假 A 级 | **采一条验一条** |

## 诚实边界

- 本 Skill 是方法与判据，不含任何具体数据
- A 级判定必须在**当次**验证，不能凭「上次能打开」
- 抽样验证的结论只能说「抽样 N 条中 X 条通过」，**不能外推为「全部可信」**
- 对标国标时要注明用的是哪一版（如 T/CIIA 060-2025），版本变化判据可能变
- 数据登记/申报的法定要求以主管部门最新文件为准
